# Phase 2B Tool Intelligence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Jarvis decides which tools a request needs at tool level (not group level), runs them safely and adaptively (parallel reads, ledger, recovery, verify), remembers structured results for references, and proves the gain with a baseline-vs-new eval, without weakening any security boundary.

**Architecture:** Extend, never replace: per-tool cards (`skills/toolcards.js`) feed a hybrid tool index (`skills/toolindex.js`) that narrows what `createToolRunner().turn()` offers; a ledger, a round runner and a recovery policy sit in/around `registry.js exec()` so `exec()` stays the only authority; owner-only working memory feeds the interpreter and the chat prompt; the orchestrator loop gets heuristic round assessment and complexity-scaled budgets. Every feature is enabled by an injected dependency (or `intelligence` flag), so the old path stays reproducible as the eval baseline.

**Tech Stack:** Node (CommonJS), `node:test` + `node:assert/strict`, Electron main wiring in `src/main/main.js`, Ollama-only provider with `constrain`, Windows host.

**Spec:** `docs/superpowers/specs/2026-11-13-phase2b-tool-intelligence-design.md`

## Review Focus
Five inputs most likely to bite; each has a test in its owning task.
1. **Untrusted read batched with a confirm call** (`[browser_read_page, close_app]` in one round): the read's result taints the turn before the confirm call is authorized; `close_app` is refused and never runs. Test: Task 4.
2. **Accidental vs deliberate duplicate write** within 60 s: an accidental repeat returns "Already done" without running; "send it again" (user words in this turn) runs it once; a model-supplied `force: true` argument never bypasses; a non-idempotent tool without `force` is never silently re-run. Test: Task 3 (ledger and exec) and Task 7 (orchestrator `force`).
3. **Guest or tainted caller asks for a tool they may not use**: top-K and `find_tools` hide it, outcome is `not_permitted` (spoken refusal, no model call), not "no capable tool"; calling it by name is still refused by `exec()`. Test: Task 2.
4. **Timed-out write**: not retried; verified through its declared `verify` read tool, else reported as "outcome unknown"; the ledger records `unknown` so a repeat within 60 s is refused without `force`. Test: Task 5.
5. **Phrasing with zero word overlap on a 300-tool registry while embeddings are slow (>250 ms) or down**: lexical fallback still returns <=8 tools plus `find_tools`, never throws, never exceeds the 250 ms cap; with embeddings up the tool is found (mode `hybrid`). Test: Task 2.
