## 1. Architecture

| Part | Where | Notes |
|---|---|---|
| Entry point | `src/main/main.js` | Electron main. Builds one `ctx` and wires everything. |
| Turn flow | `src/core/orchestrator.js` | fastPath (confirm, memory, lyrics, media skills) → router → skill-group select → provider stream → tool loop (max 5 rounds) → claim guard. |
| Router / select | `src/core/brain/router.js`, `src/core/skills/select.js` | Regex routers. Top 2 groups with score ≥ 2, else `knowledge`. |
| Tool registry | `src/core/tools/registry.js`, `tools/constrain.js` | `createToolRunner`; groups in `src/core/skills/<id>/index.js` (18 groups). `validateArgs` exists in `constrain.js` but is only used by the model-based repair. |
| Prompts | `src/core/brain/prompt.js` (+ `docs/jarvis-prompt-rules.md`), `orchestrator.js` NUDGE_* strings, `tools/*` `hint` fields, `brain/guard.js` | System prompt is built per turn from code. No prompt files on disk. |
| Providers | `src/core/providers/ollama.js` | Local only; `chat`, `constrain`, `warm`, `status`. |
| Memory | `src/core/cortex/*` (SQLite via `node:sqlite`, WAL, FTS5, int8 vectors, backups, quarantine), `src/core/memory/*` (facts, chats, extract, scheduler), `src/core/session.js` (chat JSON) | Already has transactions, integrity check, backups, hybrid recall. |
| Speech out | `voice/speech-text.js` → `voice/piper.js` (Piper) or `voice/windows-speech.js` (System.Speech via PowerShell host) → `main/mic.js` plays PCM | |
| Speech in | `voice/whisper.js`, `vad-model.js`, `speaker/*`, `controller.js` | |
| Wallpaper bridge | `src/core/bridge.js` (HTTP/SSE on 47801-47806) | Localhost, Host and Origin checks. |
| Extension link | `src/core/media/ytmusic-link.js` (WebSocket server 47830-47832, HMAC link key) ↔ `extension/background.js` | Extension is the client. |
| Extension | `extension/` (MV3): `background.js`, `page.js` (YTM commands), `browser.js` (tab commands), `tracker.js` + `logger-main.js` + `logger-relay.js` (listening log), `popup.*` | Only music.youtube.com is a fixed host permission. |
| Hosts | PowerShell: `pc/pc-host.ps1`, `media/media-host.ps1`, `voice/speech-host.ps1`; children: whisper-server, piper, kiwix | |
| Data stores | `%APPDATA%\jarvis-core`: `config.json`, `cortex.db`, `sessions/*`, `timers.json`, `music-plays.jsonl`, `actions.log`, `web-activity.jsonl`, `voice-trace.jsonl`, `jarvis.log`, `link.key`, `voiceprint.json`, `cache/` | |
| Metrics | `memwatch.js` (process memory, 60 s, in memory only); `registry.stats()` (per-tool counts, in memory only); `turn` bus event | Nothing persisted. No dashboard. |

Not seen: `src/ui/*` (read only by grep), the three `.ps1` hosts, `engines/`, the jarvis-desktop repo, and the live YouTube Music page.

## 4. Issues (prioritised)

Severity: C critical, H high, M medium, L low.

| # | Sev | Category | Where | Issue and why it matters |
|---|---|---|---|---|
| E-1 | H | extension / feature gap | `extension/*` (no code) | Nothing handles YouTube's "Continue watching?" prompt or the age/maturity interstitial, so playback stops until someone clicks. |
| E-2 | H | trust | `extension/background.js:121-134` | Commands run silently. Popup shows only the last command name; no history, no badge. "Every action visible" is not met. |
| E-3 | M | permissions | `extension/manifest.json:8-13` | `tabs` is always granted but only the optional `browser_*` commands need it (finding the YTM tab works with the host permission). Make it optional. |
| E-4 | M | connection | `extension/background.js:89-94` | No `onerror`, and the ping at :98 never expects a pong, so a half-open socket looks connected until Chrome notices. Server has the same gap (`ytmusic-link.js:123` only answers pings). |
| E-5 | M | connection | `extension/background.js:93`, `:22-27` | Backoff is reset to 2 s on every close, so a server that accepts then drops is retried every 2 s forever. No jitter. |
| E-6 | M | data reliability | `extension/background.js:101-117` | `pending` plays use read-modify-write on `chrome.storage.local`. Two plays close together both read the same array and one is lost. `flushPending` sets `pending: []` after sending, dropping plays added meanwhile. |
| E-7 | M | data reliability | `extension/background.js:111,119` | `send()` swallows errors, so a play sent into a closing socket is lost, not queued. |
| E-8 | L | connection | `extension/background.js:77-82` | Ports are probed one by one at 1.5 s each (4.5 s worst case) and `lastError` can stay stale. |
| C-1 | H | connection | `src/core/voice/windows-speech.js:64,86` | `starts >= 2` is a lifetime counter. After one crash and one restart, a second crash disables the speech, media or PC host until the app restarts. It is never reset after healthy uptime. |
| C-2 | M | connection | `src/core/media/ytmusic-link.js:57,85` | When a new extension socket replaces the old one, the old socket's `close` returns early (`sock !== s`) so its in-flight requests wait the full 15 s timeout instead of failing at once. |
| C-3 | M | connection | `src/core/providers/ollama.js:171-174` | The chat request has no connect timeout or retry; a brief Ollama restart fails the turn. `info()` failures are not cached, so each turn while Ollama is down waits up to 4 s. |
| C-4 | L | duplicate clients | `ollama.js:6`, `cortex/embedder.js:39`, `memory/system.js:22` | Three separate places build the Ollama URL and fetch; `SYSMON` health fetch is repeated in `main.js:130,506`, `checks.js:84`, `skills/system/index.js:7`. Different timeouts and error text for the same service. |
| S-1 | H | skill trust | `src/core/tools/registry.js:48-64` | `exec` never validates arguments against `tool.params`. The only check is the model-based repair (`orchestrator.js:339`), skipped when `constrainTools` is off, the provider has no `constrain`, or the call aborts. |
| S-2 | M | skill trust | `orchestrator.js:359-360` | A tool counts as success when `res.ok` and the text does not start with "error". A tool that returns a "could not…" sentence still backs an action claim. |
| S-3 | M | skill accuracy | `skills/select.js:172-186` | No confidence. A request that matches nothing silently gets `knowledge`; two close groups are not flagged, so there is no ask-or-decline path. |
| S-4 | L | skill accuracy | `test/fixtures/route-golden.json` | Only group selection has a test table; no request → tool table, and `eval/run.js` needs a live GPU model. |
| M-1 | M | memory leak | `src/core/music/log.js:39-66` | Every play is held in memory and the file is never compacted. Measured 52 MB retained at 100 000 plays. Boot also reads the whole file synchronously. |
| M-2 | L | memory leak | `src/core/pc/actions-log.js:21,48` | `entries[]` grows with every action (0.36 MB per 540, so slow). |
| M-3 | L | memory leak | `src/core/media/ytplaylists.js:40,139` | `tracks` map keeps every playlist ever opened (up to 5000 tracks each). Not measured. |
| P-1 | M | prompt | `brain/prompt.js:66` vs `:74` | "Quote tool results with at least 5 significant figures" contradicts the voice rule "Round numbers sensibly". |
| P-2 | M | prompt | `prompt.js:28-29` | "Never casual", "grammatically impeccable, Oxford or Harvard" and "Contractions are fine" pull in different directions; dialect is hard-coded. |
| P-3 | M | prompt | `prompt.js:61-70` | No guidance to plan before a multi-step request, check a result before answering, or when to ask a clarifying question (only the "Meaning" rule at :15 touches it). |
| P-4 | L | prompt | `prompt.js:81-83` | The confirm-tool list is typed out (`risk: 'confirm'` is the real source). A consistency test guards it, but it is a second copy. |
| SP-1 | M | speech | `voice/speech-text.js:83-89` | Register is hard-coded British-formal: "Okay, no problem!" becomes "Very well, not at all!". Not configurable. |
| SP-2 | M | speech | `speech-text.js:47-50` | "14:30" is spoken as "14 30". Measured. |
| SP-3 | M | speech | `speech-text.js:9,20-24` | Not normalised (measured): "1,234,567", "3rd", "5km", "2.5GB". Unit rules need a word boundary, so a number glued to its unit is skipped. |
| SP-4 | L | speech | `main.js:213` | `toLocaleDateString('en-US')` is fixed, not from the dialect setting. |
| D-1 | H | analytics | `memwatch.js`, `registry.js:21` | Metrics live only in memory and are lost on restart. No store, no dashboard, no time ranges. |
| D-2 | L | source of truth | `main.js:146` | Offline library folder `C:\JarvisData\library` fixed in code (also in the 2026-11-10 audit). |
| D-3 | L | source of truth | `extension/background.js:9` vs `ytmusic-link.js:12` | Port list written twice, with no test tying them together. |
| D-4 | M | source of truth | `memory/skill.js:33-36`, `config.user.name` vs cortex facts | Name lives in `config.json` and can also be saved as a fact. Which wins is not stated. **Not verified**: I did not trace the fact path to see whether they can disagree. |

## 5. Plan (impact, then risk)

1. **Phase 2, connections and extension.** C-1, C-2, C-3, C-4, E-2..E-8; YouTube prompt confirmation (E-1) with an off switch and a visible log.
2. **Phase 3, skill calling.** S-1, S-2, S-3, S-4: schema gate in the runner, confidence and clarify, verified results, request → skill table with before/after accuracy.
3. **Phase 4, analytics.** D-1: persistent local metrics and a dashboard page served on the existing localhost bridge, opened by a skill.
4. **Phase 5, prompts, reasoning, speech.** P-1..P-4, SP-1..SP-4: before/after prompt record, planning and verification rules, configurable dialect.
5. **Phase 6, memory and source of truth.** M-1..M-3, D-2..D-5: bounded play log, ownership document.

Each phase ends with `npm test`.
